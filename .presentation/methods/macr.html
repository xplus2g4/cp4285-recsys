MACR

Model-Agnostic Counterfactual Reasoning for Eliminating Popularity Bias in Recommender System — Wei et al., KDD 2021

Bias: popularity Mechanism: counterfactual inference Stage: training loss + inference score Family: model-agnostic (paper: MF, LightGCN)

MACR targets popularity bias. It adds two small branches to the model: one scores the item alone, and one scores the user alone. Training fits the product of all three branches to the clicks. At inference MACR subtracts what the model would predict from the item and user alone, and ranks by the remainder. The knob c sets how much is subtracted; c = 0 keeps the full prediction.

Headline result. For c ≥ 10, MACR lowers ARP@10 from 1,998 to between 1,462 and 880, at a click GAUC cost of 0.0003 to 0.0020. The price is off-target: coverage@10 halves, duration fairness worsens, and the clickbait share rises from 0.066 to up to 0.119. IPS-pop at clip 10 beats every c on both ARP and GAUC. The c = 0 row has the best diversity and duration numbers, but it uses a different learning rate, so we cannot attribute those gains to MACR alone.

The problem it targets

A model trained on the standard log learns that some items get clicked by almost everyone. In Naive MF, 95% of top-10 slots go to head items (APLT@10 0.048), and the average recommended item has 1,998 training exposures.

The paper separates two reasons for a click. The user may click because the item matches their interest. The user may also click because the item is popular and widely known (conformity). Only the first reason is personal. If the model mixes both, it shows a popular video to a user who has no interest in it, simply because many other users clicked it.

MACR's goal is to keep the personal part of the score and remove the part that comes from the item alone. Unlike IPS, it does not down-weight popular items during training. A popular item that matches the user should still rank high.

How it works

The paper draws a causal graph: a diagram in which each arrow means "is a cause of". It has four nodes: the user U, the item I, the user-item matching K, and the click Y. There are three paths to the click:

  • U → K ← I, then K → Y: the user-item match. Its score is ŷ_k, the user-item matching score. This is the existing recommender, here the MF backbone logit.
  • I → Y: the item's direct effect. Its score is ŷ_i, a logit computed from the item embedding alone. It should capture popularity and conformity.
  • U → Y: the user's direct effect. Its score is ŷ_u, a logit computed from the user embedding alone. It captures the user's general tendency to click anything.

Training

  1. Compute the three branch scores ŷ_k, ŷ_i, ŷ_u for each logged exposure.
  2. Fuse them into one prediction. σ is the sigmoid, so σ(ŷ_i) and σ(ŷ_u) lie between 0 and 1 and act as multipliers on the match score:
    ŷ = ŷ_k · σ(ŷ_i) · σ(ŷ_u)
  3. Fit the clicks with BCE on the fused prediction, plus two small auxiliary losses that make each side branch predict the click on its own:
    L = BCE(ŷ, y) + α · BCE(ŷ_i, y) + β · BCE(ŷ_u, y),   α = β = 10⁻³
    y is the click label. α and β set how strongly the item and user branches are pushed to explain clicks by themselves.

Inference

  1. The total effect (TE) is the full prediction ŷ_k · σ(ŷ_i) · σ(ŷ_u).
  2. The natural direct effect (NDE) is the prediction in an imagined world where the user and item still act directly, but the match K is fixed at a reference value c, the same for every pair. That reference value stands for "no particular match". NDE = c · σ(ŷ_i) · σ(ŷ_u).
  3. Rank by the total indirect effect (TIE), the part of the prediction that flows through the match: TIE = TE − NDE. This is counterfactual inference:
    score(u, i) = (ŷ_k − c) · σ(ŷ_i) · σ(ŷ_u)

The knob c is the reference value of ŷ_k. With c = 0 the score is the total effect: MACR's training, but no counterfactual subtraction. As c grows, an item with a large σ(ŷ_i) loses more score, because c · σ(ŷ_i) is subtracted. For very large c, the term −c · σ(ŷ_i) dominates and the ranking tends towards "lowest σ(ŷ_i) first". The paper tuned c to about 20–40.

Two properties that matter later. (1) For one user, σ(ŷ_u) is a single positive factor on all of that user's scores. It changes the size of the adjustment, but it never changes that user's ranking. Only the item branch reorders a list. (2) What reorders the list is c × (difference in σ(ŷ_i) between items). If σ(ŷ_i) is almost the same for every item, c must be very large to do anything.

In the toy, σ(ŷ_i) follows popularity exactly; in the real model it need not.

Recommender family

  1. Paper. The paper implements MACR on two collaborative filtering models: MF and LightGCN (a graph CF model). It evaluates them on five datasets (Adressa, Globo, ML10M, Yelp, Gowalla).
  2. Model-agnostic. Yes, within limits. The backbone must have the shape "user and item representations → matching score". MACR needs the matching score ŷ_k and a user and an item representation to feed the two side branches. It does not need popularity counts, side features or timestamps; the item branch learns popularity from the clicks.
  3. What we used. The shared 64-dimensional MF backbone, trained on clicks. ŷ_k is its logit; the side branches read its user and item embeddings.
  4. Other families (reasoning, not evidence). Graph CF carries over directly; the paper itself reports LightGCN. A sequential recommender has a user state rather than a fixed user embedding; the user branch could read that state, but the paper does not test this. For LLM-based recommenders, an item branch would need a separate item representation, and the subtraction would act on whatever score the LLM outputs. We know of no evidence for either case.

Our implementation

Knob grid
c ∈ {0, 10, 20, 30, 40, 60, 100}. It contains the paper's tuned range (20–40). Each value is its own sweep.
Branches
ŷ_k = the MF backbone logit, unchanged. ŷ_i and ŷ_u are linear layers on the backbone's item and user embeddings (the paper allows multi-layer perceptrons).
Loss
BCE(ŷ_k σ(ŷ_i) σ(ŷ_u)) + α BCE(ŷ_i) + β BCE(ŷ_u), with the paper's α = β = 10⁻³. α and β are not swept.
Inference
(ŷ_k − c) σ(ŷ_i) σ(ŷ_u), applied in the same way to candidate scoring (GAUC, NDCG) and to full top-10 lists.

Departure from the paper

The paper's MF has no bias terms. Our backbone keeps its per-item bias b_i inside ŷ_k, because §13 of our spec holds the backbone fixed across methods. A per-item bias is itself an item-only effect: the paper names "MF with user and item biases" as a model that already has a direct I → Y path. So part of the item's direct effect lives in b_i, inside the matching branch, and the counterfactual step does not remove it.

Why the grid goes up to 100

Before the sweeps, a check on the calibration split found that, with α = β = 10⁻³, the learned σ(ŷ_i) spans only about 0.98–1.00. Between the 1st and 99th percentiles, ŷ_k spans about −1.6 to 1.0. The push c × Δσ(ŷ_i) therefore stays small until c is large: about 0.2 at c = 10 and about 2 at c = 100. On one tuning model, that check gave a top-10 ARP of 1,968 at c = 0 and 869 at c = 100, with calibration GAUC 0.5460 → 0.5434.

Diagnostics

MACR has no per-run diagnostics in our results (unlike the IPS weight statistics). The evidence for the weak item branch is the calibration check above. We also confirmed that reloading a saved model and rescoring calibration candidates reproduces the saved scores exactly, and a unit test checks that candidate scoring and top-10 lists apply the same adjustment.

Tuned learning rate and weight decay

c = 0 used a different optimiser setting. Its tuning picked lr 10⁻³ / wd 10⁻⁶. Naive MF and every c ≥ 10 picked lr 10⁻² / wd 10⁻⁵. The c = 0 row therefore mixes MACR's training change with an optimisation change. The tables mark it lr≠. The c ≥ 10 rows share the baseline's setting, so their differences come from the method.

Findings

  • Targeted bias, c ≥ 10: popularity falls, mostly inside the head. ARP@10 drops from 1,998 (Naive MF) to 1,462 at c = 10 and 880 at c = 100, i.e. −27% to −56%, all significant (seed std 124–194). APLT@10 rises only from 0.048 to 0.074–0.090, and RSP_pop improves by only 0.06–0.10. Lists move from the most-exposed head items to less-exposed head items; few tail items enter.
  • Exposure (off-target), c ≥ 10: lists concentrate. Coverage@10 halves from 0.025 to about 0.012–0.013, and exposure entropy falls by 0.06–0.08. The same users get a smaller set of moderately popular items.
  • Accuracy and user groups, c ≥ 10: small, steady losses. Click GAUC falls by 0.0003 (c = 10, seed std 0.0002) to 0.0020 (c = 100, seed std 0.0009); NDCG@10 click by 0.0006 to 0.0030; all significant. The mainstream NDCG gap does not move (|Δ| ≤ 0.0009, not significant). At c = 100 both mainstream (−0.0025) and non-mainstream users (−0.0029) lose.
  • Duration (off-target), c ≥ 10: fairness worsens, mean length does not. RSP_dur rises by 0.20–0.26, W1 by 7–10 s, and C_KL_dur by 0.10–0.14 for c = 10–60 (at c = 100 the C_KL_dur Δ is −0.0002, not significant). Mean list duration stays within 2.2 s of Naive MF's 78.5 s.
  • Clickbait (off-target), c ≥ 10: rises with c. The share of clickbait items goes from 0.066 to 0.074 (c = 10) and 0.119 (c = 100), all significant. Its seed std grows from 0.009 to 0.040, so the high-c values are unstable across seeds.
  • c = 0, lr≠: large diversity and duration gains, with a confound. Coverage 0.025 → 0.087, APLT 0.048 → 0.20, RSP_pop −0.38, W1 −11 s, RSP_dur −0.20, C_KL_dur −0.17, clickbait share −0.023, all significant. Click GAUC is unchanged (−0.0003, CI includes 0, seed std 0.0006), but NDCG@10 click falls by 0.0034. The ARP change (−121) is smaller than the seed std (86 for c = 0, 135 for Naive MF). C_KL_pop worsens (+0.13). Mainstream users lose 0.0086 NDCG, so the mainstream gap narrows by 0.0092.
  • Pareto position (RQ4). On ARP@10 vs click GAUC, IPS-pop at clip 10 (ARP 509, GAUC +0.0016) beats every MACR setting on both axes. MACR still beats PD at similar ARP: c = 100 (ARP 880, GAUC −0.0020) against PD γ = 0.1 (ARP 1,177, −0.0085).

Discussion

Why the effect is weak and what it does. With the paper's α = β = 10⁻³, the auxiliary losses are tiny next to the main loss, and the item branch learns σ(ŷ_i) ≈ 0.98–1.00 for all items. Likely because, in addition, the backbone's item bias b_i inside ŷ_k already absorbs the item-only signal, the item branch has little left to explain. The counterfactual step can only reorder by c × Δσ(ŷ_i), so small c does little and large c is needed. Even so, top-10 lists are decided among items whose ŷ_k values are close, so a small push already moves ARP by 27% at c = 10. The push moves lists towards items with slightly lower σ(ŷ_i), which here appear to be less-exposed head items rather than tail items: APLT barely rises and coverage halves. This is the same concentration pattern as PD and moderate-clip IPS.

Trade-offs exposed. RQ1: for c ≥ 10 MACR does reduce popularity on ARP, but not on the tail-share or parity metrics, and it narrows exposure. RQ2: the off-target costs are on duration fairness (RSP_dur, W1, C_KL_dur) and clickbait, while accuracy and user-group gaps barely move. The clickbait rise also appears under IPS-pop at clip 10 (0.114). Likely because both methods demote the most-exposed items and the freed slots go to items with high click rates but poor watch quality; we have not verified this. RQ3: lowering popularity does not change the mean list length, but it does change which durations are recommended relative to what users like (W1, RSP_dur up). This is bias coupling in the distribution, not in the mean. RQ4: MACR is dominated by IPS-pop at clip 10, but it costs much less accuracy than PD for the same ARP.

Hypotheses. H3 (popularity debiasing widens the user gap, with mainstream users losing) is not supported for c ≥ 10: both user groups lose about equally. At c = 0 mainstream users do lose, but because they had higher NDCG, the gap narrows. H1 and H2 concern duration correction and IPS and do not apply directly.

The c = 0 row. Its gains come from the training change, not from the counterfactual step, because c = 0 subtracts nothing. With σ(ŷ_i) ≈ 1, its score is close to ŷ_k itself, so the multi-task training must have changed ŷ_k. But c = 0 also tuned to a 10× smaller learning rate, so its row cannot separate "MACR training" from "a different optimisation point".

Open questions. (1) Would MACR training at the baseline's lr 10⁻² / wd 10⁻⁵ with c = 0 keep the coverage and duration gains? That run would separate the training effect from the lr effect. (2) Would a larger α, or removing b_i from ŷ_k, give the item branch a wide σ(ŷ_i) range, and would that move lists into the tail instead of concentrating them?

Caveats

  • The bootstrap CIs of set metrics (coverage, entropy, Gini) are biased.
  • There is no correction for multiple comparisons across the panel.
  • * covers user sampling only, not seed variance. Some MACR effects have a seed std as large as Δ: clickbait share at c = 10 (Δ +0.0084, seed std 0.0089) and ARP at c = 0 (Δ −121, seed std 86).
  • Satisfaction cells rest on about 10% of users.
  • The c = 0 row has a different tuned lr / wd from the baseline and from c ≥ 10.
  • α and β were fixed at the paper's 10⁻³ and not swept. A larger α could give a different trade-off curve.
  • Our backbone keeps b_i inside ŷ_k, so part of the item's direct effect is never removed. Our results describe MACR on a biased MF, not the paper's bias-free MF.
  • The σ(ŷ_i) range of 0.98–1.00 comes from one calibration-only check, not from every final run.
