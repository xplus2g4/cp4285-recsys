IPS-feat

Recommendations as Treatments: Debiasing Learning and Evaluation — Schnabel, Swaminathan, Singh, Chandak & Joachims, ICML 2016 (covariate propensity). Propensity model: Factorization Machines — Rendle, ICDM 2010.

Exposure biasLoss reweightingTraining lossModel-agnostic · needs side features

IPS-feat is inverse-propensity weighting in which the propensity comes from user and item features, not from item popularity. A factorization machine (FM) learns how much more often the logging recommender showed a video with these features to a user with those features than uniform random exposure would. Its weights then go into the same weighted BCE loss as IPS-pop. The FM has no item ids, so it cannot copy popularity, and its propensity differs by user.

Headline result. At a matched ESS share of about 0.5 (IPS-feat clip 4000: ; IPS-pop clip 100: ), IPS-feat gains more GAUC · click ( vs ) but removes less popularity (ARP@10 vs ). Its largest effect is off-target: the top-10 lists get longer videos (mean duration s, against s for IPS-pop), and duration calibration improves.

The problem it targets

Every training row is an exposure from the standard log. Kuaishou's own recommender chose those exposures. A model trained on them learns the user's taste and the old recommender's choices. This is exposure bias.

Without correction, Naive MF repeats those choices. Its top-10 lists have an ARP@10 of training exposures, and the head items hold 76% of all training exposures. Its lists also have a mean duration of s, while the items users clicked in the random-exposure log average s.

IPS-pop corrects exposure with one number per item: its training-exposure count. That number is the same for every user. It cannot express that the old recommender may show a type or length of video to one kind of user more than to another. Schnabel et al. suggest a second option: estimate the propensity from user and item covariates (side features). IPS-feat is that option. The question for this project is which exposure pattern it undoes, and what that does to the biases it does not target.

How it works

Training

  1. Build features. Each (user, item) pair becomes 32 categorical codes: 25 user fields (activity degree, follow / fan / friend / register-day ranges, 18 anonymous one-hot fields, …) and 7 item fields (video type, upload type, upload date, music type, tag, orientation, and the item's duration decile in the catalogue). There are no user or item ids.
  2. Fit the propensity model. Every logged training exposure (u, i) is a positive. For each one, draw one negative (u, j) with the same user and j uniform over the 7,344 items. Redraw the negatives every epoch. Train an FM with BCE for 15 epochs:
    s(u, i) = b + Σf wxf + Σf<g ⟨vxf, vxg⟩

    Here xf is the code of field f for this pair, w is one learned weight per code, v is a learned 8-dimensional vector per code, and ⟨·,·⟩ is the dot product. The last sum covers every pair of fields. s(u, i) is the FM's logit.

  3. Turn the logit into an inverse propensity. With one negative per positive, the FM's odds estimate a density ratio, i.e. how many times more likely the log is to contain this pair than uniform random exposure:
    es(u, i) ≈ Plog(i | u) ÷ Puniform(i | u)   ⇒   ρ(u, i) = e−s(u, i)

    Plog(i | u) is the chance that the old recommender showed item i to user u. Puniform(i | u) = 1/7,344 is the chance under random exposure. ρ is the inverse propensity of the row.

  4. Weights (the same steps as IPS-pop):
    w̃ = ρ ÷ min ρ  →  w̄ = min(w̃, clip)  →  w = w̄ ÷ mean(w̄)

    The first step makes the smallest weight 1. The second caps each weight at clip. The third sets the mean training weight to 1.

  5. Train the MF backbone with the weighted loss:
    L = (1/B) Σr ∈ batch wr · BCE( f(ur, ir), yr )

    f(u, i) is the MF score, y the click label, B the batch size. Rows that the log over-represents get small weights; rows it under-represents get large ones.

Inference

  1. Score every item with the MF score f(u, i) and take the top 10. The FM is not used at inference. Scoring is identical to Naive MF; only the trained parameters differ.

Why user features act only through interactions

Each negative has the same user as its positive. A term that depends only on the user adds the same amount to both, so it cannot tell them apart. User fields therefore matter only through the pairwise user × item terms. This is why we use an FM and not the plain logistic regression of the paper: a logistic regression would drop the user side completely under this sampling.

The knob

The knob is clip, the largest allowed ratio between two weights. clip = 1 would give every row weight 1, i.e. Naive MF. clip = ∞ applies the full inverse propensity, which is unbiased if the propensity is right and has the highest variance. The amount of clipping at a given clip depends on the propensity model's tail, so we compare propensity models by ESS share, not by clip.

Recommender family

  1. In the paper. Schnabel et al. evaluate MF-IPS: matrix factorisation whose squared or absolute rating error is weighted by 1/propensity. They test it on semi-synthetic ML100K, Yahoo! R3 and Coat, with explicit ratings. The covariate (logistic-regression) propensity is used on Coat, with user features (gender, age, location, fashion-awareness) and item features (gender, type, colour, promoted). The FM we use as the propensity model is itself a feature-based (CTR-style) model from Rendle (ICDM 2010).
  2. Model-agnostic? Yes. The correction only multiplies each row's loss, so any backbone with a pointwise loss can use it. It needs categorical side features for users and items. Unlike IPS-pop, it does not need item popularity.
  3. What we used. The shared 64-dimensional MF backbone, a collaborative-filtering model, trained on clicks with BCE.
  4. Other families (reasoning, not evidence). Graph CF such as LightGCN can take the same row weights if it is trained with a pointwise loss; with a pairwise loss such as BPR, the weight has to be defined per pair. Sequential and LLM-based recommenders could reweight their training loss the same way, but the propensity would then also need to depend on the user's context, which this FM does not see.

Our implementation

Knob grid

clip ∈ {10, 30, 100, 300, 1000, 2000, 4000, 8000, ∞}. Every value is its own sweep. The first six values are the IPS-pop grid. They turned out to be uninformative here: the smallest FM weight is an outlier. Relative to it, the 1st percentile of w̃ is 68 and the median is 386. So clip ≤ 300 clips most rows ( to of rows on seed mean) and gives about Naive MF. We then added 2000, 4000 and 8000 to trace the informative range. All nine sweeps are reported. For scale: on seed 0 the unclipped max ÷ min weight ratio is about 6.4·10⁴ for the FM, against 9,110 for the popularity propensity.

Departures from the paper, and why

  • FM instead of logistic regression. The FM is the logistic regression plus pairwise feature interactions. The interactions are needed because per-user negatives cancel every user-only term (see above).
  • No random-exposure data in the propensity. The FM separates logged exposures from uniform random items drawn by us, at 1:1, so its odds target Plog(i | u) ÷ Puniform(i | u). This is the same target as IPS-pop (uniform item exposure for each user), conditioned on features.
  • Implicit clicks, not ratings. The paper weights rating-prediction errors (MSE/MAE, L-BFGS). We weight click BCE and train with Adam, like every method here.
  • Clipping. The paper names clipping as a possible improvement but does not evaluate it. We sweep it as the knob. clip is relative to the smallest weight.
  • Propensity fitted per run. The FM is trained inside each run (Adam, lr 10⁻², batch 65,536, 15 epochs; train loss 1.2507, 1.2123 and 1.2065 after 5, 10 and 15 epochs), with the run's seed. So the propensity, and the weights, change from seed to seed.
  • Side features. 25 user fields and 7 item fields, each coded 0 = missing, 1..K = sorted raw values. Near-identifiers (author id, music id) and constant columns are left out. The duration decile uses catalogue bins, not log rows.

Discussion

Mechanism → result. The FM sees item features, including the duration decile, but no item id. Its inverse propensity ranks rows only partly like the popularity one (ρ = 0.45). Weighting by it raises the training weight of rows whose feature profile the old recommender showed less often than uniform exposure would. Likely because longer videos are among those under-shown profiles, the MF learns to rank longer videos higher (interpretation; we did not fit the FM without the duration field). The lists move toward the duration users actually click in the random log, so this off-target effect happens to go in a good direction here.

Coupling (RQ3). In KuaiRand, popular items are shorter: the 200 most-exposed items have a median of s against s for the pool. So any popularity correction should lengthen lists a little. Coupling alone does not explain IPS-feat: IPS-pop at clip 100 lowers ARP@10 more () yet adds only s, while IPS-feat adds s. The popularity propensity left duration nearly fixed and worsened duration calibration; the feature propensity improves it. The coupling runs both ways, and its sign depends on what the propensity model sees.

Research questions. RQ1: partly. It lowers ARP@10 and raises coverage, but much less than IPS-pop, and APLT@10 hardly moves. RQ2: duration calibration, W1, clickbait share and entropy improve at clip ≥ 4000; the user gaps do not change significantly. RQ4: at matched ESS neither propensity dominates. IPS-feat is better on GAUC, NDCG, duration and clickbait; IPS-pop is better on ARP and APLT. On the NDCG × ARP plane, IPS-pop clip 10 (NDCG , ARP ) dominates IPS-feat unclipped (, ); on GAUC × ARP it does not. H2: coverage rises ( → ) and seed variance rises in the transition range clip 300–2000, unlike IPS-pop; we have no direct tail-precision measure. H3 is not supported: the mainstreaminess gap does not change significantly. H1 does not apply, since this is not a duration method; the opposite move (to longer videos) appears as an off-target effect.

The trade-off this method exposes. "Exposure bias" is not one thing. The choice of propensity model decides which exposure pattern is undone: item popularity (IPS-pop) or a feature profile that includes length (IPS-feat). The same name, IPS, then has opposite effects on duration and clickbait.

Open questions. (1) Is the duration shift caused by the duration-decile field? Re-fitting the FM without that field would test it. (2) Would a propensity model with both item ids and features combine IPS-pop's tail shift with IPS-feat's accuracy, or only add variance?

Caveats

  • The bootstrap CIs of set metrics (coverage, entropy, Gini) are biased.
  • There is no multiple-comparison correction across the panel.
  • * covers user sampling only, not seed variance. Several IPS-feat effects (clickbait, APLT, duration at clip 1000–2000) have seed std close to Δ.
  • Satisfaction cells rest on about 10% of users.
  • The matched-ESS pair is approximate ( vs ), and IPS-pop clip 100 was tuned to lr 0.001 while IPS-feat stays at 0.01. Part of that comparison is an optimisation difference.
  • The clips 2000, 4000 and 8000 were added after the first six were seen to be uninformative. The grid is therefore partly post hoc.
  • The propensity AUC () is measured on training positives against fresh negatives. It is a fit diagnostic, not a held-out check that the propensity is correct.
  • The FM is re-fitted with each seed, so seed std mixes MF training noise and propensity-model noise.
